# Dr-Web-Test

Решения тестовых заданий на C/C++. Каждая задача лежит в своей папке, к части задач есть тесты на GoogleTest.

## Сборка

Нужны CMake 3.31+ и компилятор с поддержкой C++20. Проект проверялся на компиляторе MSVC 2022. GoogleTest скачивается автоматически через `FetchContent`. Проект также открывается в CLion.

```bash
cmake -S . -B build
cmake --build build --config Debug
```

Запуск тестов:

```bash
ctest --test-dir build -C Debug --output-on-failure
```

## Задачи

### 1. Разбор заголовка архива — [`arc_parse/`](arc_parse)

Переписанная функция `ParseXXX`, которая разбирает заголовок архива неизвестного формата и проверяет, похож ли он на настоящий архив.

- `ParseArchiveHeader()` читает фиксированные поля (версию, размеры сжатых и распакованных данных), имя файла, комментарий и дополнительное поле. Затем проверяет, что сжатые данные целиком помещаются в файл.
- Для сжатых версий (1 и 2) есть эвристика: по гистограмме байтов первых 32 КБ проверяется, что данные похожи на сжатые, то есть распределены почти равномерно.
- Коды возврата совпадают с оригиналом: `NotRecognized`, `BrokenComment`, `Recognized`.
- Вместо глобального файла и функций `fSeek`/`fRead` используется класс `ArchiveStream`, который читает из памяти. Поэтому парсер можно тестировать без файлов.
- Исправлены ошибки оригинала:
  - комментарий больше не затирает имя файла;
  - сумма `смещение + размер` считается в 64 битах и не переполняется;
  - на слишком маленькой выборке эвристика не выполняется, поэтому граница частоты не уходит ниже нуля.

Тесты: [`tests/archive_parser_test.cpp`](tests/archive_parser_test.cpp).

### 2. Поиск строк в буфере — [`keyword_search/`](keyword_search)

> Написать класс, в котором есть метод для поиска в заданном буфере строк `company`, `atnauthor`, `datafield`, `generator`, `atndate`, `gridtbl`, `atnid`, `g`, `creatim`, `ftnsepc`. Исключения не использовать, объект класса создавать динамически и память под объект выделить самостоятельно (placement new).

Класс `keyword_search::KeywordSearcher`:

- Поиск идёт по алгоритму Ахо–Корасик: буфер проходится один раз, и за этот проход проверяются все 10 слов.
  - Находятся все вхождения, в том числе перекрывающиеся, например `g` внутри `generator`.
  - Сравнение побайтовое и учитывает регистр. Буфер не обязан заканчиваться нулём.
- **Без исключений.** Все методы `noexcept`. Автомат хранится внутри объекта в массивах фиксированного размера, поэтому класс не выделяет память и не может получить `bad_alloc`. Библиотека собирается с `/EHs-c-` (MSVC) или `-fno-exceptions`.
- **Placement new.** Конструктор и деструктор закрыты. Объект создаётся только так:

  ```cpp
  KeywordSearcher* searcher = KeywordSearcher::Create(); // std::malloc + new (memory) KeywordSearcher()
  if (searcher == nullptr) { /* не хватило памяти */ }

  Match matches[32];
  std::size_t found = searcher->FindAll(buffer, size, matches, 32);

  KeywordSearcher::Destroy(searcher);                    // ~KeywordSearcher() + std::free
  ```

- `FindAll()` записывает не больше `capacity` совпадений вида `{offset, keyword}` и возвращает, сколько совпадений найдено всего. Если передать `nullptr, 0`, метод только считает совпадения. `ContainsAny()` останавливается на первом совпадении.

Тесты: [`tests/keyword_searcher_test.cpp`](tests/keyword_searcher_test.cpp). Среди них есть сравнение с наивным поиском на случайных буферах.

Пример использования: [`main.cpp`](main.cpp).

### 3. Ассемблер → C — [`asm_to_c/`](asm_to_c)

> Переписать на C:
>
> ```asm
> push ebp
> mov  ebp, esp
> mov  eax, [ebp+8]
> neg  eax
> sbb  eax, eax
> neg  eax
> pop  ebp
> ret
> ```

```c
int IsNonZero(int value)
{
    return value != 0;
}
```

`neg eax` ставит `CF = 1`, если аргумент не ноль. `sbb eax, eax` даёт `-CF`, то есть `0` или `-1`. Второй `neg` превращает это в `0` или `1`. Остальные команды — пролог и эпилог функции `cdecl`.
